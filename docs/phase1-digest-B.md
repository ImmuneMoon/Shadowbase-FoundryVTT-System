## builders-customization

1. Every structural slot is `{partId, materialId?, wrapId?, inventoryId}`; resolution prefers the owned inventory row (`resolveRangedSlot`, `resolveMeleeEntry`, `resolveLightsaberSlot`, `resolveSlotPart`) and falls back to partId, with `chosenNotOwned` feeding a shopping list.
2. `buildProvenance` ('placed'|'built'|null) is stored once at creation; 'built' consumes owned rows via `consumeForWeaponBuild(rows, consumes, itemId, 'melee'|'saber'|'blaster')` or `consumeForBuild` for armor, marking rows isInstalled/installedIn*Id rather than deleting.
3. `slotScope(templates, ownedCount, freePlacement, keep)` (part-acquisition.ts) decides every dropdown's options: owned rows in campaign mode, the whole catalog under "Direct Library Access".
4. Blaster: `calculateBlasterStats(blasterData, weaponModifications)` returns finalDamage/finalDamageType/finalAccuracy/finalHalfDamageRange/finalRateOfFire/finalWeight/finalCost/finalBulk/finalRecoil/finalST/notesAndEffects/maxDurability/condition/energyRes/malfunction/totalUpgradesCost; price = `assembledMarketPrice([partsCost, fittedModsCost], loadedAmmoValue, rangedMarkup(profileCategory, buildCarriesSilicon(parts)))` with rangedMarkup = (bowcaster/flamethrower/launcher/gauntlet ? 3 : 2) × (Silicon ? 3 : 1); Ch11 parts priced by `rangedComponentValue = ceil(trunc2dp(volume×density) × costPerLb) × 2`; family and skill re-derived from the fitted parts (`deriveRangedClassification`, `RANGED_FAMILY_SKILLS`); mod slots from `rangedModSlotsFor(category, baseSkill)` via 9 classes, stored as 13 pairs `<slot>ModId` + `<slot>ModPartId`.
5. Melee: slots are LISTS (gripParts/headParts/guardParts/utilityParts with quantity) because 19 of 37 profiles carry two components in one slot; durability scales with quantity, parry/ST do not; components price by `componentShelfPrice = ceil(volume×density×costPerLb) × 2`; whole-weapon stats (damage modes from head.damageBonus, ST-based damage via getDamageString, parry, Min ST, unbalanced, price at `meleeMarkup(hasPowerUnit)` = 2 × (powered ? 3 : 1)) now in `calculateMeleeWeaponStats`.
6. Lightsaber: hilt parts price by `hiltSlotPrice = ceil(raw material value × 3)`; internals at printed cost; total = `assembledMarketPrice([handgrip, internals], 0, 3)`; a fitted coupler makes it a staff (`isStaffHilt`) replacing the pommel, adding emitterTwo/switchTwo/sleeveTwo and doubling shared cell/lens/matrix but not per-blade crystals (`tallySaberInternals`, `internalIsSplitPerBlade`); blade damage is Model B: `(primary.baseDamageDice + emitter.damageMod + powerCrystal.damageDice)d + adds` energy, no crystal = no blade; classType from `lightsaberClassType(sides)` is the specialty string Lightsaber Combat (X); assembly now in `calculateLightsaberStats`; `composeLightsaber(design)` is the inventory-blind composer for Blueprints.
7. Armor pieces are DERIVED: `derivePiece({location, tier, material, sealed, frame, trim, wiredBacking})` = Shell + Backing + Frame (Light/Standard/Heavy = 1/2/4 mod slots) + Visor + Trim; baseCost = ceil(sum × 2), marketCost = base × 2, DR = roundHalfUp(BASE_DR × drMultiplier). `calculateModifiedArmor(item, armorModifications, characterSM, hitLocations)` is the armor engine (SM-scaled weight, limb pricing, four mod slots contributing flat DR / typed DR / location bonus / DX-Move penalties / conditional bonuses, Beskar and padding typed DR, condition off drEntries vs `listedArmorDrAt`). Rules: `armorModSlots/canFitMod/modFitProblem/hostsPoweredMods` (powered mods need a Wired Backing), `armorFit` (|ΔSM| ≥ 1 Ill-Fitting −2 DX/−1 Move, ≥ 2 Unwearable), `enforceBaseLayer` (one base layer per location per limb space; face Upper/Lower/Full), `armDRFromTorso = floor(0.65 × torso DR)`, `assignToLimb/splitPerLimb`, `presetSuitItems` deals suits one row per limb. Items and hit locations join by uuid: `drEntries[{locationId, dr}]`, `coveredLocationIds`, `wornLocationId`.
8. Starships: `deriveStarship(ship)` is pure (chassis base + DP mods + STARSHIP_MODS via `starshipModCost` as hull percentages with `starshipModFittingLimit`; weapon tokens parsed into armaments; Weapon Upgrade (Damage) = 35% of the paired gun; systems via `initialSystems/mergeSystems`); the DP builder's DP_COSTS/DP_GAINS live only in starship-builder.tsx (app-own, no book citation).
9. Droids: droidBuild is one actor-level object (chassisId, powerCoreId, head{componentId, processorId, coProcessorId, memoryCoreId, sensorIds[] sparse, externalModId, customHeightM}, arms[], legs[], chassisMods{internalIds[] sparse with Backup Power Array at 99, externalIds, utilityIds, auxiliaryIds, motiveMountIds, reinforcementId, armorId, armorCurrentDr, shieldActive, shieldCurrentDr, shieldEmitterCondition, motivatorId, actuatorId, wiringId}, warpedSlots[]); derivations are pure: `fittedDroidRows` → `calculateDroidHardwarePoints` (CP once per distinct part id unless cpStacks) and weight; `getPrimaryAttributes` gives ST = chassis.st, IQ = `governingDroidIq`, DX = 10 + upgrade dxBonus, HT 10; `droidAnatomy` derives T20 hit locations; `droidHardwareDr` keeps frame vs plating DR separate plus the Shield Projector field; `deriveDroidSm` from height. Part installs on a built droid roll Ch17's swap procedure (`DROID_PART_SWAP`, 30 min) with 1d6 failure tables applied by `droidMalfunctionApplication`; parts are consumed from and returned to equipment rows BY NAME.
10. Implants/prosthetics: `planImplantBuild({chipWeight ∈ [0.1,0.2,0.5], traitCp, noFirmware})` = (chip × 50 CR/lb + |CP| × 20) × 6 × 3; `planProstheticBuild({scope, material, modules, jerryrigged, sizeModifier})` = SM-scaled chassis (PROSTHETIC_CHASSIS at CHASSIS_MARKUP 4) + Neural Interface + Power Cell + modules ≤ MODULE_CAPACITY; `prostheticQuality` reads Phase 2/3 margins; installation recorded in `hitLocations[i].installedHardwareIds`. Side effects: `implantModifiers/implantConditionalBonuses/implantCpCharges` (CP charged only when installed and not bought as Advantages), `requiredMandatoryFlaws/missingMandatoryFlaws` (Electrical −20, Daily Maintenance −10, Susceptibility −1 for implants, Unhealing (Partial) −20 for limbs), `missingExtremities`.
11. Crafting: `CRAFTING_DEFINITIONS` (CraftingStage[] per family, ~39 priced families), DECONSTRUCT/SWAP definitions, LIGHTSABER_FORGE/DISASSEMBLY/SALVAGE stages, `stagesForSilicon/stagesForPowerUnit` gates, `markupSteps/craftedPrice`, `baseTimeMinutes`, WORKSPACE_MODS, EXTRA_TIME_STEPS, `computeYield`, `materialLossFraction`, `stageSkillChoice/stagesAsCrafted/criticalFailureOutcome`. The run UI (inventory/crafting-dialog.tsx, 1659 lines) takes {item, category, mode: forge|disassemble|deconstruct|salvage|swap|swapComponent|standard, weaponCarriesSilicon, blueprintWrite, designPhase, declaredBlueprintId} and returns CraftingResultMeta {outcome, wasCriticalFailure, marginOfSuccess, isOverloaded, isUnattuned, isFractured, componentRuinedStage, saberForgeRuin, prostheticQuality, installation, consumedByFailure, blueprintWritten, ...}; its stage-selection tree exists only in that component.
12. Blueprints are equipment rows with blueprintOf/blueprintGeneration/blueprintProven/blueprintLocked/blueprintFlawed/blueprintParts/blueprintBricked/blueprintOrigin/blueprintMarkup/blueprintFamily; blank Datacard 174 CR / 0.28 lb; `blueprintBuildBonus(gen, proven) = (proven ? 0 : −1) − gen`; every build requires its plan in hand; `craftableDesigns()` prices ~477–491 designs; `planBlueprintBuild` routes a card to a flat build or the right designer.
13. Function firmware (belts, shields, face gadgets): FIRMWARE_BANDS are GM ranges, `comparableFirmware`, `authoringDays` = 1 day per 1,000 CR, `finishedItemPrice = (housing + circuit + cell + fee + 20 × CP) × 2 × 3`.
14. Gear sets: `recogniseSets/resolveCustomSet/unmatchedWornGear` read the armor list (setId stamp wins over name match), `applySetEquip` equips through `enforceBaseLayer`, `activeSetBonuses` grants Ch13 set bonuses; storage is a `storageLocationId` on every row plus `storageBoxes[]`; item transfer uses the versioned envelope with a parts closure (`collectPartsClosure`) and shape-sniffed Zod import.
15. The website persists every derived final* field via hook setValue so the HUD/exporter can read unmounted cards; in Foundry these are `item.derived` except genuine state (durability/durabilityTwo through `trackedDurability`, armor `drEntries[].dr`, `isUnready/lastAttackTurn`, starship `systems[].hp`, droid `armorCurrentDr/shieldCurrentDr`).
16. Difficulty estimates for Foundry sheets: blaster Medium; melee Medium-High; lightsaber High; armor Very High (four builders plus actor-level anatomy/layering/body loadout); starship Low-Medium; droid High; implants/prosthetics Medium; ammunition/parts shop Medium; shared CraftingApplication High; gear sets/storage/transfer Low.
17. Open: `tallyRangedMods` tallies rangeMult and cpsMod but `calculateBlasterStats` returns finalHalfDamageRange unmodified and never writes charges-per-shot; melee currentCharges/maxCharges fill 100/100 on first measure; `hiltType` is written by the factory but not in lightsaberSchema.

## foundry-v13-api (verified against the 13.350 API site, release notes, the CLI source and live systems)

1. Foundry serves the system statically at /systems/shadowbase/, so a module can `import` the ESM engine bundle directly.
2. Since 13.341 default Actor/Item sheet registrations were removed: register sheets in `init` via `foundry.documents.collections.Actors.registerSheet` / `Items.registerSheet` (or `DocumentSheetConfig.registerSheet`).
3. Data models: subclass `foundry.abstract.TypeDataModel`, `static defineSchema()` with `foundry.data.fields`, register with `Object.assign(CONFIG.Actor.dataModels, {...})` in `init`, AND declare every sub-type in `system.json` `documentTypes` (unprefixed names, e.g. `"Actor": {"character": {"htmlFields": [...]}}`) — the server rejects undeclared types.
4. prepareData order: system.prepareBaseData → Actor.prepareBaseData → prepareEmbeddedDocuments (items/effects prepare, then `applyActiveEffects()`) → system.prepareDerivedData → Actor.prepareDerivedData.
5. `NumberField` is nullable by default; DataField defaults are required:false/nullable:false/initial:undefined; use `{required:true, nullable:false, initial:0}` for anything an ActiveEffect will ADD to. `StringField`/`HTMLField` default `trim: true`. `SchemaField` cleaning drops undeclared keys; `ObjectField` is opaque.
6. ApplicationV2: static `DEFAULT_OPTIONS` (merged up the chain), static `PARTS` (HandlebarsTemplatePart: template, templates, scrollable, classes, id, forms; one root element per part), static `TABS` ({tabs:[{id,icon,label,tooltip,cssClass}], initial, labelPrefix}) with `this._prepareTabs(group)` in `_prepareContext` and `context.tab = context.tabs[partId]` in `_preparePartContext`, and an `actions` map of static handlers `(event, target)` bound by `data-action`. Constructors take a single options object (`new Sheet({document})`). Static initialisers run before CONFIG.SHADOWBASE exists, so template paths are hard-coded.
7. DocumentSheetV2 form pipeline: tag 'form' by default, inputs bind by full dotted name, `_prepareSubmitData` → `_processFormData(event, form, formData)` → `_processSubmitData(event, form, submitData, options)`; embedded-item inputs are stripped by validation unless extracted in `_processFormData` and applied via `updateEmbeddedDocuments`.
8. ActorSheetV2 ships drag/drop: elements with class 'draggable' and data-item-id/data-effect-id route to `_onDropItem/_onDropActiveEffect/_onDropActor/_onDropFolder/_onSortItem`; plain ApplicationV2 apps wire `foundry.applications.ux.DragDrop` manually.
9. DialogV2 statics: `confirm()` → true/false/null, `prompt()`, `input()` → form-data object or null, `wait()` → button action id or callback value; `rejectClose` defaults false; callbacks receive (event, button, dialog).
10. Rolls: `await new Roll(formula, actor.getRollData()).evaluate()`; `roll.total`, `roll.dice[0].results[i].result`; `roll.toMessage({speaker, flavor}, {rollMode})` or `ChatMessage.create({author, speaker: ChatMessage.getSpeaker({actor}), style: CONST.CHAT_MESSAGE_STYLES.OTHER, content, rolls:[roll], flags})`; `CHAT_MESSAGE_TYPES` no longer exists; `renderChatMessageHTML(message, html: HTMLElement, context)` replaces renderChatMessage; context-menu hooks are `get<Document>ContextOptions(application, menuItems)`.
11. ActiveEffect: `changes[{key, value (string), mode, priority}]`, `CONST.ACTIVE_EFFECT_MODES` CUSTOM 0 / MULTIPLY 1 / ADD 2 / DOWNGRADE 3 / UPGRADE 4 / OVERRIDE 5, mode non-nullable since 13.334, priority defaults mode×10, CUSTOM fires `applyActiveEffect`; `CONFIG.ActiveEffect.legacyTransferral` is false (item effects apply from the owned item). `CONFIG.statusEffects` is an ARRAY of {id, name, img, hud?, changes, duration}; `actor.toggleStatusEffect(id, {active, overlay})`; `actor.statuses` is a Set.
12. Token bars: `primaryTokenAttribute/secondaryTokenAttribute` are system-relative paths resolving to {value, max}; `CONFIG.Actor.trackableAttributes` restricts choices; `Actor#modifyTokenAttribute(attribute, value, isDelta, isBar)` is the override point.
13. Initiative: `CONFIG.Combat.initiative = {formula, decimals}` in init; `Combat#rollInitiative(ids, {formula, updateTurn, messageOptions})`; combats unlinked across scenes by default.
14. Packs are LevelDB directories at `packs/<name>` (no .db); `system` required for Actor/Item packs; `ownership` maps USER_ROLES to DOCUMENT_OWNERSHIP_LEVELS; packFolders. foundryvtt-cli: `compilePack(src, dest, {yaml, recursive, log, transformEntry})`; every source file MUST carry `_key` (`!items!<id>`, `!actors!<id>`, `!journal!<id>`, `!folders!<id>`) or is silently skipped; embedded documents stay nested; keys absent from the source are deleted on compile; Foundry must not have the world open while packing.
15. JournalEntry pack sources nest `pages` of type text with `text {content: HTML, format: 1 (HTML) | 2 (MARKDOWN)}`; cross-links use `@UUID[Compendium.shadowbase.handbook.JournalEntry.<id>.JournalEntryPage.<pageId>]`.
16. Handlebars: `foundry.applications.handlebars.loadTemplates({"shadowbase.item-row": path})` registers named partials; core helpers include localize, selectOptions, formGroup/formInput, numberFormat, eq/ne/lt/gt/and/or; `<range-picker>` and `<prose-mirror>` custom elements supersede rangePicker and {{editor}}.
17. Enrichment: `await foundry.applications.ux.TextEditor.implementation.enrichHTML(raw, {secrets, rollData, relativeTo})`; custom enrichers in `CONFIG.TextEditor.enrichers`.
18. Globals moved to foundry.* namespaces with deprecation redirects until v15 (TextEditor, FilePicker, loadTemplates/renderTemplate, mergeObject, Actors/Items); Application v1 under foundry.appv1 survives until v16; hooks and `_onRender` receive HTMLElements.
19. CSS: v13 uses CSS Layers and ThemeV2; `styles` entries may be `{src, layer}`; ApplicationV2 roots carry `.themed.theme-light/.theme-dark`; checkboxes are Font Awesome icons styled via ::before/::after.
20. Settings: `game.settings.register(namespace, key, {name, hint, scope: 'world'|'client'|'user', config, type, choices, range, default, onChange, requiresReload, filePicker})`; `registerMenu` accepts an ApplicationV2 subclass. Hot reload: `flags.hotReload {extensions: ['css','hbs','json'], paths: ['styles','templates','lang']}`.
21. Unverified: `TokenDocument#getBarAttribute` return shape; exact trackableAttributes shape; some field option boolean defaults; HotReloadData shape; core CSS layer names; LOCALIZATION_PREFIXES key layout; whether the CLI validates `_id` format (it does not appear to).
